P0 — Hotfixes

Ship first: functional dead-ends or hard keyboard blocks.

critical AF-P0-1 Design + Engineering Page APage C Claude · af5f0eba6Cursor · axe

Entire demo renders in a grey theme at ~2:1 contrast

Cursor independently measured every themed control on this demo: "I'm new here", "Contact me" and "Select all" at rgb(169,169,169) on rgb(240,240,240) = 2.06:1; "Justin Ware", "Test User" and "Continue" white-on-grey = 2.35:1. 8 of 9 measured controls fail AA. Matches Claude's finding exactly.

Fix. Investigate the missing/failed brand theme assignment for this demo, and add a contrast-safe token fallback so a themeless demo cannot ship below 4.5:1 (3:1 for UI boundaries).

Independently confirmed by Cursor computed-style measurement

Evidence screen grabs (3)
critical AF-P0-2 Design + Engineering Page C Claude · af5f0eba6Claude · by teamCursor · axe

Topic-rating checkboxes render at 0×0 and are unreachable by keyboard

Cursor confirmed all 6 rating inputs (2 topics × 3 ratings) return width 0 / height 0 from getBoundingClientRect() with tabIndex 0 and no accessible name. Chrome's sequential focus skips zero-dimension elements regardless of tabIndex, so keyboard-only users cannot rate topics — and rating is required to continue. Third demo where this reproduces.

Fix. Give the input real dimensions matching the visible star/check/X icon (or move focus to a sized sibling), then add aria-labels. Fix once at the shared component.

Independently confirmed by Cursor getBoundingClientRect() probe

Evidence screen grabs (3)
critical AF-P0-3 Design + Engineering Page C Claude · by teamCursor · axe

Rating controls are checkboxes implementing mutually-exclusive radio behavior

Cursor observed the 6 inputs share one name per topic (da4cbc5f… and b26ca434…), i.e. radio-group semantics implemented with type=checkbox and no role=radiogroup/radio.

Fix. Convert to role=radiogroup + role=radio (or native radios) with per-option labels, alongside the hit-target fix.

Independently confirmed by Cursor DOM probe (shared name attribute)

Evidence screen grabs (1)
serious AF-P0-4 Engineering Page D Claude · af5f0eba6

Product tour close (X) button does not respond to clicks

Claude observed two click attempts failing to dismiss the tour overlay, stranding the visitor. Not reproducible by Cursor this pass — tour sits behind the rating gate and inside a cross-origin iframe.

Fix. Check click handler / hit-target registration and z-index or event propagation on the tour close control.

Claude-only — not reproduced by Cursor

No Cursor screen grab — see note above for why this finding could not be captured live.
